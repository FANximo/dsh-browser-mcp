# 浏览器接管 · 防封号规则（Agent 必读）

账号风控看三件事：**访问频率**、**行为像不像人**、**是否自动化特征明显**。
下面第 1 节是配置层已做的（v1.1.0），第 2 节是 Agent 每次操作必须遵守的，第 3 节是立刻停手的红线。

## 1. 配置层（已生效）

| 项目 | 设置 | 作用 |
|---|---|---|
| 浏览器 | 真实 Microsoft Edge 157（channel=msedge），非 headless | 内核/UA/TLS 指纹与普通用户一致 |
| 登录态 | 持久化 profile `launcher/profile` | 一直是同一台设备同一会话，不做反复登录 |
| 自动化特征 | `--disable-blink-features=AutomationControlled` + `stealth.js`（去掉 navigator.webdriver、补齐 window.chrome、锁定 zh-CN 语言） | 削减「这是脚本」的 JS 侧信号 |
| 语言/时区 | locale=zh-CN，timezone=Asia/Shanghai | 与真实用户位置一致 |
| 动作节奏 | `slowMo: 150ms` + 每次动作后 `settle: 1500ms` | 单次操作最少间隔约 1.5 秒，接近人手速度 |
| 空闲回收 | `idle: 30 分钟` 无调用自动关浏览器，下次调用再拉起 | 不留长时间挂机的自动化窗口 |
| 页面注册工具 | `webmcp: false` | 不让网页自行注册可被 Agent 调用的工具（防钓鱼） |
| 文件访问 | 默认限制在工作区内 | 防止误读本地文件 |

## 2. 操作节奏（Agent 必须执行）

1. **单次会话内，页面跳转 ≤ 20 次**；超出就在同一页面用 evaluate 读数据，别反复导航。
2. **两次导航之间至少隔 3–5 秒**（配置已给 1.5s，需要更慢的场合自己加 `browser_wait_for`）。
3. **不批量翻页**：搜索列表最多看 2–3 页；需要更多就换关键词，不做「1 到 20 页全扫」。
4. **不做高频轮询**：同一页面 10 分钟内不重复刷新超过 2 次；补货监控靠定时任务（每 3 天一次），不靠连刷。
5. **写操作克制**：加购/改数量/删除购物车这类动作，一次会话内 ≤ 5 次，每次间隔 ≥ 5 秒。
6. **不进「我的淘宝-设置/安全中心/支付」这类敏感页**；不点开扫码、实名、绑卡相关入口。
7. **不在同一时间段处理多件事**：读订单和比价分两次会话做，别一个会话里连开十几个页面。
8. **夜间（00:00–06:00）不做批量浏览**，人类这个点在睡觉。

## 3. 红线：出现以下任一情况立刻停手

- 页面出现 **滑块 / 短信验证 / 「请完成安全验证」** → 立即停，交给用户手动处理，不要尝试自动过验证。
- 出现 **「访问异常」「系统检测到当前访问存在异常」** → 立即停，至少 30 分钟内不再访问该域名。
- 出现 **登录失效、要求重新扫码** 且不是用户主动退出 → 停手并告知用户，可能是风控降权信号。
- 淘宝要求 **绑定手机 / 实名 / 人脸** → 绝对不自动继续。
- 同一会话连续 3 次页面加载慢或返回空 → 停手，报告情况。

## 4. 永远不做

- 不自动下单、不自动支付、不自动确认收货（涉及钱的动作用户自己点）。
- 不改收货地址、不改手机号、不动账户安全设置。
- 不用脚本批量抓取商品详情/评价（这类高频请求最容易触发风控，已实测被拦）。
- 不把登录态/profile 复制给别处使用。

## 5. 升级到新版本后怎么验证

1. 重启 DSH（`restart-required` 时必须）。
2. 让 Agent 调一次 `browser_navigate` 打开 `https://www.taobao.com`，确认仍是登录态。
3. 出错时看 `runtime` 目录下的 stderr 日志；配置文件是 `launcher/playwright-mcp.config.json`。
